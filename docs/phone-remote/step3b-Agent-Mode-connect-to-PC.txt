Now connect the app to my PC. REMOTE_API.md in the project root is the contract that my PC app (Agent Arcade) implements. Read all of it and follow it exactly: paths, field names, status codes, close codes and limits. Add a NetworkArcadeRepository that implements ArcadeRepository with it:

1. Libraries: OkHttp for REST and the WebSocket, kotlinx.serialization (ignoreUnknownKeys = true, explicitNulls = false, coerceInputValues = true, encodeDefaults = true; always send every field of a request or WebSocket message, such as type, submit and lines, even when it has a default), and the Google code scanner (com.google.android.gms:play-services-code-scanner) for QR codes, which needs no camera permission. Keep the versions in the version catalog.

2. Pairing. The pairing link looks like agentarcade://pair?v=1&name=…&hosts=ip:port,ip:port&code=…&fp=<64 hex characters> (section 1 of REMOTE_API.md). Get it from the QR scanner, from "Paste pairing link" (the clipboard, or a text field), or by opening such a link (an intent filter for the agentarcade scheme with host pair). Show a confirm sheet "Pair with DESKTOP-ARCADE?" with the short fingerprint (the first 8 bytes, colon separated, like 3F:A2:91:0C:7B:44:E1:D0) so I can compare it with my PC. On OK, POST /api/v1/pair with the code and the device name (Settings.Global DEVICE_NAME, else Build.MODEL), trying the hosts in order with a 4 s connect timeout. Show clear errors in the app's style for a wrong or expired code, a PC that can't be reached ("Same Wi-Fi? Phone remote on? Wi-Fi set to Private on the PC? Windows firewall?") and a certificate that doesn't match.

3. TLS: accept only the paired certificate. Use a custom X509TrustManager whose checkServerTrusted computes SHA-256 over chain[0].encoded and compares it in constant time with the paired fp, and a HostnameVerifier that accepts the host only on this pinned client. No trust-all code anywhere, no cleartext traffic (usesCleartextTraffic false).

4. Storage: the PC name, hosts, last host that worked, fingerprint and deviceId in DataStore. The device token encrypted with an Android Keystore AES-256-GCM key (not the deprecated EncryptedSharedPreferences).

5. Connection: one ConnectionManager in the AppContainer with the states Connecting, Live, Reconnecting, Offline(reason) and Unpaired. Open wss://<host>/api/v1/live with the Authorization header and OkHttp pingInterval 20 s. On hello, replace the whole state; apply session, closed, state, history, attention and screen events to StateFlows. Reconnect with backoff (1, 2, 4, 8 s, then every 15 s), and right away when the app comes back to the foreground or the network changes (ConnectivityManager.NetworkCallback). Try the last host that worked first. When State has hosts (the PC's current addresses), store them as the PC's hosts, keeping the last host that worked first, so a changed address or a newly installed Tailscale is learned while connected. Ignore callbacks from any WebSocket that isn't the current one: the PC closes a phone's older connection with 1000 when the phone reconnects. Disconnect when the app goes to the background (the next step adds staying connected). HTTP 401 or close code 4401 means Unpaired: clear the pairing and show Connect with "This phone isn't paired any more. Pair it again on your PC."

6. Actions: map every ArcadeRepository function to its REST endpoint. Show the PC's { "error": "…" } sentence in a toast in the app's style (#1D1D23, strong border, 11dp corners). 503 = "Agent Arcade is busy, try again".

7. Switching: the Connect buttons now work. "Try the demo" and Settings > Demo mode keep using DemoArcadeRepository. The app opens on Agents when it is paired, on Connect otherwise. Settings > Your PC shows the real PC name, its address, the paired date, the fingerprint and the live status. "Forget this PC" calls POST /api/v1/unpair (ignore errors), clears the storage and goes back to Connect.

8. Local network permission: Android 17 blocks apps that target SDK 37 or higher from reaching local network addresses (192.168.x.x, 10.x.x.x and the like) without the ACCESS_LOCAL_NETWORK runtime permission (in the Nearby devices group). Declare <uses-permission android:name="android.permission.ACCESS_LOCAL_NETWORK" />. When the device runs Android 17 or newer and the app targets 37 or higher, request it before the first pairing attempt and before connecting, after a short sheet in the app's style: "Agent Arcade Remote talks straight to your PC on your Wi-Fi. Android asks you to allow that (Nearby devices)." If it is denied, show "Allow Nearby devices for Agent Arcade Remote so it can reach your PC on Wi-Fi" with a button that opens the app's settings, and still try the hosts (a Tailscale address may work). Don't request it on older Android versions.

9. Unit tests: pairing link parsing (a good link, missing fields, a bad fp), parsing of every JSON example in REMOTE_API.md, and the fingerprint check.

Build and run. Without the PC, check in the emulator that Connect, the pairing errors and demo mode all work.
